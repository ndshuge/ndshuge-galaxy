# Apple Motion Lab R2.6｜底栏按压、拖动与释放的柔和连续性

基线：R2.5，已发布的 whole-dock 版本；开发方式：ChatGPT 直接使用 Mice Hole 本机工具，独立 worktree，未交给 Codex 或其他 Agent。

## 用户发现的问题及根因

R2.5 底栏存在四项独立的运动不连续因素：

1. 外层底栏与选中玻璃的弹簧过硬：外壳 `stiffness=480,damping=37`，透镜抬升 `520/39`，按压位移虽小，但过于集中在最开始的几十毫秒。
2. `pointerdown` **立即**触发光学材质参数重建，首次 SVG 位移图生成有概率阻塞渲染。某些 Windows Edge 冷启动测试中，第一帧出现较长软件渲染停顿。
3. 内部透镜的形状在触摸开始后的 **120ms** 才由额外计时器启动，造成第二段突兀鼓起。
4. 松手之后，高度弹簧又被人为延迟 **110ms**，同时视图 **立即**把折射图标切成静态图标，造成“视觉先跳变，物理稍后落下”的断层。

## R2.6 的具体修复

| 状态 | 新机制 | 旧版 |
|---|---|---|
| 按下 | 底栏 spring 立即响应，约48ms后再进入复杂折射层；触摸开始不再同步改写需要重新生成的镜片参数 | 按下时切材质并立刻重建位移图 |
| 底栏整体抬升 | `createSpring(175,27,1)`，压缩、移动与高光跟同一个连续 press 值 | `createSpring(480,37,1)` |
| 底栏水平方向 | `createSpring(155,25,1)` 跟随手指，幅度仍十分克制 | `420,34,1` |
| 玻璃形变 | `createSpring(265,33,1)` 立即参与按下与速度反馈 | `610,40,1`、加延迟120ms |
| 玻璃抬升 | `createSpring(190,27.5,1)`，避免第一瞬间抬得太快 | `520,39,1` |
| 松手 | 形状与高度同步物理回落；折射副本直至两者真正归零才切回清晰图标 | 高度延迟110ms；原始图标立即切回 |
| 材质高光 | 一个持续的基底材质；高光通过 spring 能量及 CSS 缓动变化 | `.is-scrubbing` 立即切换两个不同背景 |

保留原有光学引擎 `lib/liquid-glass.js`、`components.js` 的真实 SVG 滤镜、缓存和 `fluid-contour.js`，没有发明第二套假玻璃。底栏专属的 `nav-shell-motion.js` 与 `nav-scrub.js` 调整，不触碰独立方形/分段按钮、播放器共享元素、音频和 WebGL 艺术封面。

### 物理响应预估

以仓库原有 Skill `createSpring` 采用的 120Hz 数值积分方法，对 **不受浏览器主线程阻塞**的单位阶跃作模型估算：

- 底栏整体位移达到90%：旧弹簧约 **150ms** → 新弹簧约 **308ms**。
- 内部玻璃抬升达到90%：旧约 **142ms** → 新约 **283ms**。

**此为物理模型推算，不是 Apple 官方调参，也不是用户 iPhone 真机帧率。** 实际 Edge 逐帧采样在某些冷启动场景出现较长 rAF 间隙，因此绝不将不可靠的单次帧时间当作 iOS 性能实测。真实交互仍需 iPhone Safari 验收。

## 测试与真实证据

| 测试 | 最终结果 |
|---|---:|
| R2.5 底栏整体运动与排版（320/390/768/1440） | **29/29** |
| 原播放器功能回归（desktop/mobile/narrow） | **28/28** |
| GPU/音频/弹簧压力与 reduced-motion | **14/14** |
| 原导航四视口按住左右移动 | **28/28** |
| 静止双影、拖动不规则折射、松手清晰 | **25/25** |
| 新增快按、二次接管、无脏副本检查 | **7/7** |
| **合计** | **131/131** |

证据均来自本机 Windows Edge / DevTools 触摸模拟，**不是 iPhone Safari**。压力测试中使用的 SwiftShader rAF 指标不等于真机 FPS。新快按脚本测试按住0/20/60/140ms及动画期间再次操作，保证延迟折射启动没有引入丢点击或静止重影。

最初一次整套功能回归中，播放器反向动画在固定等待时间内仅归位到进度0.039，而后续重测 **28/28 通过**。另有一次冷启动 320px 同时启动多套测试时，在前280ms未观察到整栏变化；为此增加“外层弹簧优先、光学层随后开启”的分阶段策略，复测 **29/29 通过**。这些非稳定结果没有当作用户真机已优化的证据。

## 尚未达到 Apple 原生的部分

- Apple 系统 Liquid Glass 的系统级折射、深度与触觉仍不可在纯 GitHub Pages 网页精确复刻。
- 极端首次冷加载仍可能被 WebKit SVG 贴图解码阻塞；本次延迟复杂光学启动以确保基本触摸反馈，但未获得 iPhone 真机的主线程/能源剖析。
- 视觉检查曾存在独立的 gradient/covered-text FAIL，当前 R2.6 不涉及其他页面重构。
- R2.6 的 48ms 分层时序与弹簧常数是待真机调校的工程假设，不是从 Apple SDK 读取的真实常数。
