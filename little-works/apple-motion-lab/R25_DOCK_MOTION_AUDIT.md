# Apple Motion Lab R2.5｜整条底栏的运动与排版精修

2026-10-28。基线：R2.4 commit `39e3456`。仅修改现有 `ndshuge/ndshuge-galaxy/little-works/apple-motion-lab/`，不影响其他作品和现有方形/segmented 按钮。

## 真实视频对照：为什么 R2.4 仍显得不像 Apple

用户的新录屏 `ScreenRecording_10-28-2026 19-24-53_1.mp4` 时长 **20.57 秒，512×1112，30fps**，展示的是我们自己的 R2.4（0～6s 为底栏拖动，6s 后切换播放器/方形控件）。

与之前收到的用户上传 iOS 参考录屏 `ScreenRecording_10-28-2026 18-40-10_1.mp4` 比较：
- **R2.4 仅内部透镜响应拖动**。整条暗色长方形容器的外形、位置和高光几乎不变；独立的椭圆/液体选中层偶尔越出外框。
- **参考 iOS 底栏是整体材料系统**：中间选中区域与外层柔和材质同时呈现轻微移动/形变/高光变化。这里的“整条底栏也会动”是用户指定的设计目标，参考片段仅支持*视觉行为*，不能解析内部系统物理常数。
- **当前标签更密、更小，图标描边偏细**；参考的图标/文字是统一视觉单元。Apple 参考为浅色四栏原生应用；此产品保留深色三栏布局，不能用像素误差百分比宣称 1:1。
- 方形/分段切换已经有独立合适的动效，**不应把整条底栏的响应错误地套在这些按钮上**。

### R2.5 的两类交互系统

| 区域 | 物理反馈 | 范围 |
|---|---|---|
| 底栏内选中透镜 | 继续使用已有的 `lg-navbar` SVG 光学、`fluid-contour`、`nav-scrub` 指针跟随、透镜形变、松手提交 | 不变 |
| **底栏外层整体材料** | 新 `lib/nav-shell-motion.js`，复用 Skill 的 `createSpring`，在按下时让整条 `.nav-container` 上移、微伸展/压缩，并沿手指左右微位移、倾斜，同时高光中心随触点更新 | **仅 #navWrap / #navigation** |
| 方形分段、播放控制及其他 UI | 继续使用原有 Motion / CSS 反馈 | **未修改** |

#### 工程细节

- 整个 dock 的位置只做 CSS `transform`，不是重新改变每个图标的 `top/left` 导致布局跳跃。最长幅度刻意控制：约上抬 **2.6px**，横向伸展约 **1.3–1.4%**，纵向压缩约 **2.2%**，方向倾斜至约 **0.2°**。这些是本项目**待真机调校的假设**，不是 Apple 官方参数。
- 触摸位置的光学热点通过 `--dock-shell-touch` 控制底栏环境高光；按压力经弹簧 `--dock-shell-energy` 协调。整条 dock 和内部透镜都有独立弹簧，但同一组手势事件驱动。
- `nav-shell-motion.js` 在按下时只计算一次 dock 几何位置；拖动时不持续触发 `getBoundingClientRect()`，避免额外布局读取。松手用原生物理弹簧回到静止状态。
- 字体：390px 视口下底栏按钮/复制层标签 **11.115px**，图标 **20.5px**，非选中 `font-weight:540`，选中 `610`；图标与标签 `gap:2.5px`、两层一致基线。320px 下标签 10.5px，768+ 下 11.25px。
- R2.4 的静止双影修复仍然有效：静止显示原始清晰按钮；按住进入折射副本；释放恢复单层文字。
- 未改首页大标题、专辑、音频、WebGL、mini/full 共享元素、方形分段控件。

## 仍待真机验证与后续设计方向

1. 当前用户录屏是实际 iPhone Safari，但**此次新版验证仍只有 Windows Edge CDP 模拟**；需要在真实 iPhone 上观察材质刷新、能耗、长按、反向和 Safari 工具栏干扰。
2. iOS 原生 Liquid Glass 的底层折射和触觉能力是系统合成结果，网页不能保证逐像素复刻。
3. 深色三栏与参考原生浅色四栏、不同 icon glyph 的先天差异仍在；不要为了“1:1”擅自改变产品信息架构。
4. 若真机上整体 bar 运动过于轻微或夸张，应校准整栏上抬/压缩幅度，不要再盲目加大选中透镜的拉伸。

发布 SHA 与线上检测必须单独完成后才记录为成功。没有强推或覆盖其他作品。
